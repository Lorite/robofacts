# Changelog

## 0.1.0 (unreleased)

The framework of a robotics lab's experiments, extracted into two installable packages: `robofacts` (Python only, `pip install`) and its ROS 2 backend `robofacts_ros2` (`ament_python`).

- A Crazyflie example without ROS 2 (2026-11-25): `examples/cflib_hover` is its own project on the `process` backend. One Crazyflie hovers on its Flow deck, commanded with cflib: the action refuses before arming on a fresh stop latch, a missing Flow deck, a low battery, an unsettled estimator or a ground position away from the origin, takes off in two stages, and lands on the end of the hover, on a signal, on the stop latch, at a geofence and on any error (an `estop` latch cuts the motors). The gate reads the battery and the Flow deck over the radio with two checks of the project, the drone's reset is a power cycle over the radio, and the verify step reads the recorded height. Its tests need no drone and no radio (a fake drone for the hover logic). Neither package changed for it.
- README section "What a backend must provide" (2026-11-25): the required launcher and recorder with each method, the optional fields of `Backend` with their defaults, and the two shipped implementations as examples.
- `backend:` in `trials.yaml` is required (2026-11-25): there is no default backend. Without the line every command stops with the line to add (`$TRIALS_BACKEND` still overrides for one session). `trials init` writes it, `process` unless `--backend` names another. A project of the ROS 2 package adds `backend: ros2`.
- The folders of an experiment are named by the backend (2026-11-25): on the `process` backend `recordings/`, `recordings_issues/`, `recordings_slim/`, `recordings_issues_slim/`, `recordings_scratch/` and `recordings_scratch_slim/`, on the ROS 2 backend the `bags*` folders as before (`Backend.record_dirs`, `backend.record_dirs()`). The coverage index, the decisions about a trial (`trials exclude`, `restore`, `amend`), the metadata audit, `trials records`, the runner, the scaffolding and the web interface read the names from there. `--recordings-root` is a second name of `--bags-root`, and `recording_dir_writable` a second name of the check `bag_dir_writable` (no new script, so the core still ships 8 checks). The record fields `bag_storage` and `bag_dir` keep their names. The example and the experiment template of the general package use the new names. A copy with `trials new --from` leaves out the recording folders of both schemes.
- The web interface is general (2026-11-25): `trials ui` and its pages are part of `robofacts` (Flask as the optional extra `robofacts[ui]`). A backend extends the interface through its feature `ui` (`TEMPLATES`, `template_globals()`, `layouts()`, `register(ui)`), and its `_viewers.html` replaces the general one. The ROS 2 backend's extension, `robofacts_ros2.ui_extension`, adds the Foxglove replay links and layouts, the Viewing page, the slim-bag download for the viewer and the clean slate of the rig hosts. Explore is offered only when the backend has the feature `explore`. On the lab's data, served read-only, the pages of the interface are the same before and after, apart from six reworded tooltips and hints.
- An example without ROS (2026-11-25): `robofacts/example_project` holds one experiment on the `process` backend, `demo_log_recorder`. A script stands in for the system under test and appends lines to a log file, the recorder stores what it writes during a trial, a verify step reads the recording, and the campaign `grid` sweeps two factors (`rate`, `duration`), so the coverage index shows four cells. `robofacts/quickstart.sh` runs the loop on it from the linter to the coverage index, and the CI job `core-no-ros` runs that script on `python:3.10-slim` with only `robofacts` installed. The core's tests run against this example, never against a project that lies above the working directory, and they need neither git nor `pgrep` (the tests of the code version are skipped where git is absent).
- Two packages (2026-11-24): the repository holds `robofacts/` (the general package: declarations, planner, linter, coverage index, the trial loop, the gate protocol with 8 general checks, the launcher and recorder interfaces, the `process` backend) and `robofacts_ros2/` (the ROS 2 backend: launcher, bag recorder, bag readers and slim copy, 13 ROS 2 gate checks with their sentences and concurrency classes, the robot adapters, the ROS 2 lint rules L2, L5, L11 and L16, Explore, the web interface, `kill_ros.sh`, the talker template). `robofacts` has no `package.xml` and depends on PyYAML only. `robofacts_ros2` depends on it. `robofacts/test/test_core_is_free_of_ros.py` fails the build when the general package imports a ROS module, names ROS in any file, or loads a ROS module on import. What changes for a project: (1) `trials.yaml` names the backend, `backend: ros2`, and without the key a project runs on `process` (a ROS 2 `launch:` block is then refused with the line to add). (2) The command is `trials` (on the PATH after sourcing a colcon workspace, or after pip) or `ros2 run robofacts_ros2 trials`. `ros2 run robofacts trials` no longer exists. (3) Modules that moved are imported from `robofacts_ros2`: `bag_io_utils`, `slim_bag`, `slim_bag_archive`, `export_rosout_text`, `explore*`, `pose_sample`, `ui`, the adapters (`robofacts_ros2.adapters.<name>`), the bag-reading half of `trial_media`, and `build_record_command` and the heavy-topic rules of `record_profiles` (`robofacts_ros2.record_profiles` re-exports the rest). (4) A check script that sources the helper file by a path of the old layout needs the new path (`$PF_LIB` is unchanged when the gate runs it). (5) `colcon_workspaces` is still read on the ROS 2 backend, `build_workspaces` is the general key. `trials init --backend ros2` writes a ROS 2 project. The dry-run commands, record topics, gate checklists, stop patterns and lint results of a robotics lab's 118 campaigns are identical before and after, apart from the paths of the moved modules.
- Backends (2026-11-24): the trial loop no longer names ROS 2 where it starts the stack and records the trial. `robofacts/backend.py` defines two interfaces that return command lines, a `Launcher` (`parse`, `command`, `stop_patterns`) and a `Recorder` (`command`, `has_data`, `holds_data`, `unsettled_reason`, `after_trial`, and `noun`, the word for one recording), and a `Backend` object that holds them with two optional hooks (the default setup files of a host, a step before the gate's machine checks). `trials.yaml` names the backend with `backend:`, `$TRIALS_BACKEND` overrides it, and a project that names none runs on `ros2` as before. The ROS 2 code is behind the interfaces in `robofacts/backends/ros2/` (`ros2 launch`, `ros2 run`, `ros2 bag record`, the completeness test of a bag, `rosout.txt`, the slim copy, the daemon restart before a gate). `robofacts/backends/process.py` is a second backend without any middleware: `launch: {command: ...}` starts the stack, and `python3 -m robofacts.backends.process_recorder` stores what the system appends to the files of `record_sources` during the trial, finalized by `recording.json`. `record_sources` is a second spelling of `record_topics` in `runner.yaml`. The process backend refuses `launch.package` and `launch.file` with the line to add to `trials.yaml`. Commands, record topics, gate checklists and stop patterns of a robotics lab's 118 campaigns are identical before and after.
- Lint rule L6 binds every experiment (2026-11-24): `runner.yaml` declares at least one verify step, or a written reason why it has none (`no_verify_steps: <reason>`). Before, the rule looked for flight words in the action and in the factor levels, so only an experiment that flies had to check its recording, although a ground robot whose action exits 0 while it stands still produces the same false trial. The lint cannot know from a declaration what moves, so it asks every experiment and accepts a reason. Both keys together, or a reason that is not a sentence, fail the rule. The example experiment now has a verify step (`scripts/verify_chatter.py`, at least 3 recorded messages), as the generated experiment already had.
- One host registry (2026-11-16): `common/config/hosts.yaml` declares how to reach each `execution_host` level once (`local`, or `host`, `container`, `container_hostname`, `shell` and the setup files), and an experiment's `runner.yaml` `hosts:` lists its levels and writes only what differs (`host_registry.py`). A robotics lab had 18 full copies of these settings, and one level had drifted to three ssh aliases, two of which did not reach the robot computer on the lab's network. `RIG_HOST` replaces the ssh alias of the registry's `rig:` level, the same variable `estop.sh` reads. A trial on a level that its experiment does not declare is now refused instead of running on the runner's own machine. A project without `hosts.yaml` works as before.
- The stop follows the trial (2026-11-16): a robot in `robots.yaml` names a `host_level`, resolved through `hosts.yaml` (`host_registry.robot_targets`). The runner notes each trial's `execution_host`, robots and simulation flag in its run marker (`run_marker.note`), and `estop.sh` and `robot_action.sh` send a hardware trial's robots to its host. `--host-level` overrides for one call. A simulation never moves a stop, and a marker whose runner process is gone is ignored (`run_marker.read_live`). `estop.sh --list` and the stop output name each robot's host and the reason, the runner prints the targets at the start of every hardware trial, and the web interface's clean-slate button resolves its hosts the same way. Before, a trial on the laptop sent the stop to the robot computer unless the operator remembered `RIG_CONTAINER`.
- A stop typed inside a container runs there only when it is the target's own container (2026-11-17): `container_hostname` of the host level must match the current hostname. Before, any container counted, so a stop typed in a laptop's container for a stack on the robot computer stayed on the laptop. `robot_action.sh` follows the same rule (it had no container check and tried `docker exec` inside a container). `estop.sh --list` prints a `route:` line per robot, and the runner's line says `here, in this container` when that is the route. `TRIALS_DOCKERENV` lets tests point the container check at a file of their own.
- The core names no robot and no lab (2026-11-09): `test/test_core_names_no_robot.py` fails the build on a robot family or a lab name in a core file, with a short allowlist for facts about third-party tools, and on internal issue numbers anywhere in the package. The comments, docstrings and docs lost the issue numbers and the lab's robot, rig and experiment names, and keep the reason and the date of each lesson. What a slim bag drops is the core's generic image, depth and point-cloud patterns plus the project's `slim_topics: {heavy_patterns, light_suffixes}` in `trials.yaml` (a lidar's clouds and a debug overlay used to be core rules), and `HEAVY_TOPIC_PATTERNS` resolves on access. `pose_error_analysis` left the package (its rows are one project's data format), and its `PoseSample` record is `robofacts.pose_sample`. The defaults of `camera_frames` (`topic=/camera/color/image_raw`) and `ros_clean_slate` (`pattern=component_container`) no longer name one lab's devices, and the web interface reads a lease table from any enabled adapter that offers `LEASE_TABLE`.
- Robot adapters (2026-11-09): what only makes sense for one robot family left the core for `robofacts/adapters/<name>/`, enabled per project with `adapters: [...]` in `trials.yaml`. `crazyflie`: the gate checks `battery`, `crazyflie_radio_battery`, `drone_armable` and `ekf_convergence`, the verify steps `verify_flight_happened` and `verify_ext_pose_age`, `rosout_trim_utils` (its generic `detect_storage_id` and `stamp_to_float` moved to `bag_io_utils`), and the default `cf_name`. `spot`: `graph_nav_localized`, the lease table of the web interface, and the default `spot_name`. `px4`: `px4_preflight_pass`. Each adapter declares its checks' concurrency and spoken sentences. Check lookup is the project, then the enabled adapters, then the core, and a check of a disabled adapter fails validation with the adapter to enable. The core has no default names any more. `watchdog_health` left the package (a check of one project's node). The stop sweeps' project-specific names became `trials.yaml` `stop_patterns:` (`recorder_scripts`, `owned_containers`, `kinds`), and `parallel_safe_checks:` lets a project's own read-only checks share a gate batch. A robotics lab's 44 gate checklists (626 machine entries) resolve the same checks with the same concurrency and sentences, and its stop patterns are identical.
- Record profiles are project data (2026-11-09): the package no longer ships a robot's topic sets. A project declares its profiles in `experiments/common/config/record_profiles.yaml` (reusable `blocks`, `profiles` that list blocks and extra `topics`, an optional `size` note, `{name}` placeholders from `trials.yaml`), and `trials init` writes a commented template. The runner reads the profiles of the experiments root it was given, not of the working directory. The fallback profile `position_only` is gone: a trial without a `record_profile` factor and without `record_topics` uses `default_record_profile` from `trials.yaml`, else the runner refuses it. The skeleton contract's `record_profile` enum is `[custom, unknown]`, and `record_profiles --list` prints the profiles in force. A project that relied on the profiles shipped before this change copies them into its own file (a robotics lab's 18 profiles produce the same topic lists and the same record commands for all 98 of its campaigns).
- Gate check `ros_param_equals` reads array parameters (2026-11-09): Humble prints them as `Double values are: array('d', [...])`, which the check could not parse, so a list parameter always failed as unreadable. Declare `expected=[-0.6, 0.7]`; the lists compare element by element, numbers numerically, the rest as text.
- A record profile for a teleoperated drone seen by a quadruped's hand camera (2026-11-09): the hand-camera replay profile plus `/joy`, the camera's replay-grade pixels of a drone the pilot flies on a gamepad, as detector training data. Its enum entry is in the skeleton and example contracts.
- A record profile for visual-inertial flights seen by a quadruped's hand camera (2026-11-05): the hand-camera profile plus the drone's camera frames, its IMU and a visual-inertial estimator's topics, so the quadruped's estimate of the drone and the drone's VIO land in one bag with mocap truth. Its enum entry is in the skeleton and example contracts.
- Robot resets, a pre-launch check stage and spoken NO-GO reasons (2026-11-04). `common/config/robots.yaml` gives a robot a `reset:` list (`{name, command, when, required, only_with}`) and `runner.yaml` declares `robots:` (names, or `{name, with: [features], reset}`); the runner runs the declared robots' resets before every trial, and a campaign opts out with `robot_reset: false` (`robot_resets.py`). A checklist entry with `"stage": "pre_launch"` runs before the stack starts, between `runner.yaml`'s setup steps and the robot resets, with the same NO-GO handling; the T-0 gate runs every other entry and `trials gate` all of them (`PreflightGate.with_stage`, `stage_checks`). The result goes into the trial's `preflight` block as `pre_launch`. New check `crazyflie_radio_battery` (cflib over the radio, before the stack). On a NO-GO the voice speaks at most three failed checks in plain sentences (`gate_speech.py`, an entry's `"speak"` or a built-in sentence per check type), and `GateResult.failed_items` carries them. The dry run prints the setup groups, the resets and the pre-launch checks.
- First and repeat trials of one runner invocation (2026-11-04, where a 16 s square forced a battery swap and a re-placement of the drone before every trial): operator steps, `runner.yaml` `setup_steps` and a new campaign-scoped `setup_steps` take `when: first | repeat | always` (default `always`). The first trial of a run gets the `first` and `always` steps, the later ones the `repeat` and `always` ones, and a trial after a blocked one starts over as first. A repeat trial whose operator steps all drop out still waits once on a ready step. The campaign's setup steps run after the runner's and before the launch, the place of a reset between trials. The gate, the pose pause and the stack restart stay on every trial. `--dry-run` prints each trial's operator steps and setup step names, the ledger records `step_set`, the UI labels a step that is not `always` and lists the campaign's setup steps in its automatic sequence, and lint L4b checks a campaign's setup steps (placeholders, `when`) while L7 checks their scripts.
- Gate check `topic_value.sh topic= field= [min=] [max=] [vary=true] [window_s=2] [min_samples=5]` (2026-11-04): a sensor stream is alive, not only flowing. The median of a field (`values[i]` of a `LogDataGeneric`, or a dotted path) is at least `min` and/or at most `max`, and with `vary=true` it is not constant over the window. Born for a drone's optical-flow sensor, which came up stuck after a boot (squal 0, shutter frozen at 900) while `flow_log` streamed at 50 Hz and `topic_rate` passed. Parallel-safe (a subscription).
- `trials reverify <exp> <trial> --reason … [--campaign] [--by] [--dry-run]` (2026-11-04, where a receive-rate rule written for the mocap flights failed a valid Flow-deck-only hover): runs the trial's CURRENT verify steps again, rendered as the runner renders them from the factor values of its `runs/attempts.jsonl` line, every step even after a failure, on the full bag or else its slim copy, and writes `reverification.json` beside the bag and its slim copy (each step's command, return code and output tail, the code version, who, when, why, the previous records). The coverage index lifts the abort only when the runner's `abort_reason` starts with `verify step` (the action returned 0), every current step passes, and the record was written against that same reason, so an action failure is never lifted. A failing re-verify is recorded and never excludes a trial on its own. `trials records` shows the re-verify beside the status, and slim copies carry the file. Run it on the host that recorded the trial: the archive mirrors that host with `rsync --delete`.
- A person's decision about a recorded trial is a file beside it, never an edit of `trial_metadata.json` (2026-10-22, from a rig day, where one trial walked another route than planned and one broke on a network stall). `trials exclude <exp> <trial> --reason … --category infrastructure|operator|estimator|other [--by] [--evidence]` moves the bag and its slim copy into `bags_issues*` with an `exclusion.json` beside each, and refuses a trial the runner may still be writing. `trials restore` moves it back and keeps the old reason as `exclusion_restored_<time>.json`. `trials amend <exp> <trial> <factor>=<level> --reason …` writes `corrections.json` (field, recorded, corrected, date, by, reason), checked against the experiment's levels. The coverage index applies the corrections on top of the recorded metadata, so the plan, `trials records` and the UI count the trial in its true cell and say that a correction exists. An excluded trial shows its category and reason in `trials records`, the index report and the UI, and the UI's quarantine button became an exclude form that asks for both, with a restore form on an excluded trial. Slim copies carry both files.
- Every page has an outline of its sections on the left on wide screens, built from its headings, with the current section marked (2026-10-22). On a campaign page the T-0 gate history folds into one summary line (counts and the last verdict), opened by a NO-GO on an operating UI, and in `--view-only` mode the "Before you run" checklist starts folded, so the trial cards come right after the plan.
- `card: {first: plots}` in `config/trial_media.yaml` puts a trial's result plots before its camera and video on its card (2026-10-22), for an experiment whose result is a plot, such as a map. A trial without a plot keeps its camera first.
- The trial lists open as cards by default (2026-10-22): `?view=` in the URL still wins, then the viewer's last choice, then the cards. Without JavaScript the table remains the whole page.
- A run marker (2026-10-22, `run_marker.py`): while the runner executes a trial or a campaign (never a dry run), `<experiments root>/.robofacts_trial_running.json` exists, with the host, the process, the experiment, the campaign and the start time. A campaign holds one marker across all its trials, so the gaps between flights are covered too. Tools that move data off a trial host wait while it exists, so a copy never competes with a flight for the network. A marker older than 12 hours is a leftover of a killed runner and counts as absent.
- `trials ui --view-only` serves a full recording as a password-protected download (2026-10-22), for a trial archive on a server. A UI on a trial host still refuses it, because it shares the rig's network with the flights.
- A campaign's cells now match trials on every factor with a metadata key, not only the factors the campaign names (2026-10-21). A factor the campaign leaves out is planned at its default, so a trial recorded at another level of it no longer counts (a campaign that named no `world` had claimed the flights of another world). A trial that never recorded a factor counts at its default, unless an alias maps the missing key (`None`) to another level, which keeps older trials apart when a factor's default changes.
- Renamed to `robofacts` (2026-10-16), RoboFACTS in the SAC 2027 paper: Factors, A Contract, and checked Trials in Simulation and on hardware. The Python module, the ROS 2 package, the repository (`Lorite/robofacts`, GitHub redirects the old address) and the colcon install directory (`lib/robofacts`) follow the name, so it is `ros2 run robofacts trials …`. The command `trials`, the `TRIALS_*` environment variables and `trials.yaml` are unchanged. Until this date the package was `declarative_robot_trials`.
- One command, `trials`, with the planner, the runner, the coverage index, the linter, the T-0 gate, the named analyses, the web interface and the shell tools as subcommands. `ros2 run robofacts trials <subcommand>` works the same.
- The experiments root and the project root are configurable: a flag, an environment variable (`TRIALS_EXPERIMENTS_ROOT`, `TRIALS_PROJECT_ROOT`), a `trials.yaml` found by walking up from the current directory, or the nearest `experiments/` directory. No hardcoded path remains.
- `trials init <dir>` creates a project with the shared configuration, and `trials new <name>` an experiment from a commented template that passes the linter, the planner and a dry run as generated.
- Spoken operator cues: a campaign's `voice_cues` and the runner's `voice_announce` reach a laptop voice daemon over UDP (`operator_voice.py`), printed only when `TRIALS_VOICE=off`.
- The project-specific names left the code: the stop latch path and the record profiles' robot, camera and node names are project settings in `trials.yaml`, with neutral defaults in the package, and every environment variable the package reads starts with `TRIALS_`.
- A project may ship its own gate checks in `experiments/common/preflight/checks/`; they take precedence over the packaged ones.
- `trials tool --help` lists the packaged tools and an unknown name fails with that list, `trials lint` passes pytest flags through (`trials lint -k rule_L5 -x`), and `trials ui --help` works without Flask, which only the interface itself needs (found while rewriting the docs to the command, 2026-10-14).
- The code stamp of a trial also describes the build: for each colcon workspace (`colcon_workspaces` in `trials.yaml`, else `.` and `ros2_ws`), the HEAD of every source repository under `src/` and the newest `install/` time, and `possibly_unbuilt` names the repositories committed after that build. A slow build query no longer costs the commit. The stop and action scripts bound the command inside the container too, so a hung stop cannot keep running there after the local client gives up.
- The page of an action that echoes a quadruped's `LeaseArray` states who holds the body lease in one line, with a table of every resource (the tablet held it unseen through four trials on 2026-08-10).
- A verify step for pose loss read from the drone itself, `verify_ext_pose_age` (2026-10-14): the on-board `locSrv.ageMs` of every `/<drone>/ext_pose_age` topic over the IS_FLYING window, with a declared threshold and run length, per-drone requirements (always, or only when airborne, waived before a declared date or on the simulation backend) and a one-line JSON summary for a metadata probe. The server's `Motion capture rate off` warnings, which the 2026-10-07 bags proved a bookkeeping artifact, play no part.
- Gate check `rigidbody_near.sh name= (x= y= | node= [param_prefix=]) [max_m=0.25]` (2026-10-29): a rigid body stands within `max_m` of a point sampled now, the point given in the checklist or read from a live node's parameters (`initial_position.x/.y` of a teleop node), because a teleop node that integrates stick velocities from a fixed origin drags the drone to that origin at the first setpoint. Record profile `teleop_shadow_flight` (a project's shadow-flight profile plus `/joy`), with its enum entry in the skeleton contract.
- Gate checks: `topic_rate.sh` takes an optional `max_hz` (a rate that must stay below a ceiling, for a level defined by a slower stream), and the new `ros_param_equals.sh node= param= expected=` compares a live node parameter with the trial's level, numerically for numbers.
- The fast path for a new experiment (2026-10-14, after creating one took an agent 44 minutes): `trials new <name> --from <existing> [--campaign <c>[:<new>]]` copies and renames a similar experiment's declarations (and a campaign) without its recorded data, notebooks or tests, `trials validate <experiment | campaign>` runs check, plan, every gate checklist's validation, the lint and the tests of that experiment and a dry run per execution host, and prints one READY or NOT READY verdict, and `trials lint --experiment <name>` lints one experiment.
- `kill_ros.sh` matches the install and build trees of any `*_ws` colcon workspace, not only `ros2_ws`, so a node of an overlay workspace (OpenVINS in `~/ov_ws`) no longer survives the clean slate.
- The T-0 gate runs on the trial's execution host (2026-10-14): a laptop-driven trial on a rig used to be gated on the laptop's processes, disk, network and stop latch. The checklist travels with the command, the verdict records `ran_on`, and an ssh failure is an error. A host spec may name `env_setup` files (an overlay workspace), and the files a spec names are sourced also when the runner executes locally inside that host's container, for the commands and the gate. The web UI's remote helpers imported `remote_exec_utils` from the wrong package level since the split, so its remote gate, stops and viewers raised ImportError; fixed, with a guard test.
- From the second adoption test of the SAC 2027 paper (2026-10-15): `trials new --from` copies a top-level or `scripts/` file only when a declaration names it, directly or through another copied file, and lists the rest under "Left out" (the source's AGENTS.md, design notes and study scripts), while an unnamed `config/` file is copied and listed for review. A code version that the probe cannot read now carries `code_version.warning`, which the runner prints as a WARNING, and a git worktree whose `.git` file names a path missing on this host (a host-made worktree used in a container) is named with its remedy, a relative `gitdir:` line.
- `kill_ros.sh` kills only the processes of the caller's `ROS_DOMAIN_ID` (read from each process's environment, unset means 0), lists the ones on other domains as left alone, and `--all` restores the kill-everything run (2026-10-15), so sessions that share a container on different domains no longer stop each other's trials.
- The test suite points at the example project through an autouse fixture, not through environment variables set at import (2026-10-15). A project that collects the package's tests next to its own (one `pytest.ini` over both) kept the example project's roots for its own tests too: under pytest 8 its config lint then checked one experiment instead of all of them, and its project-settings tests failed, in the full run only.
- The web interface, redrawn from scratch (2026-10-16): one information architecture, Experiments › experiment › campaign › trial. An experiment page lists every trial on one row (cell, status, campaign, slim bag with Foxglove and the experiment's layout, video, the analyses that include it, gate verdict, run log, metadata, code version), with blocked attempts and scratch flights, filters by campaign, status and factor, and no cap. A campaign page reads as a plan with the gate's verdicts and a per-cell count of refused attempts; a trial page plays the video and shows the verify report; an analyses page previews a cohort (`trials analyze` without `--execute`); a files view serves results and run logs read-only. Every feature of the earlier interface is kept, and its old addresses redirect.
- The words of the paper (2026-10-16): what a user reads now uses the terms the SAC 2027 paper defines, and the README has a glossary that maps each term to its file or key (file names and keys are unchanged). The planner prints wanted, covered and STILL MISSING per cell; every trial has the paper's class (usable, unverified, or excluded with its reason: aborted, quarantined, no data, scratch), and an attempt the gate refused is an attempt without a trial (`trials records --status excluded|attempt`); the gate prints `=== T-0 GATE ===`, `[gate]` and `CLEAR TO START`; the contract's messages say metadata contract and coverage axis (`factor: true`); generic text says run and action where it said fly; diagnostics are scratch recordings; the linter's rule L13 names the silent error it prevents. The machine-read tokens (GO, NO-GO, PASS, FAIL, `CHECK(S) FAILED`, `action returned rc=`, the ledger's status values) are unchanged.
