# Changelog

## 0.1.0 (unreleased)

The framework of the robotics lab's experiments, extracted into an installable ROS 2 package (`ament_python`, also `pip install`).

- Renamed to `robofacts` (2026-10-16), RoboFACTS in the SAC 2027 paper: Factors, A Contract, and checked Trials in Simulation and on hardware. The Python module, the ROS 2 package, the repository (`Lorite/robofacts`, GitHub redirects the old address) and the colcon install directory (`lib/robofacts`) follow the name, so it is `ros2 run robofacts trials …`. The command `trials`, the `TRIALS_*` environment variables and `trials.yaml` are unchanged. Until this date the package was `declarative_robot_trials`.
- One command, `trials`, with the planner, the runner, the coverage index, the linter, the T-0 gate, the named analyses, the web interface and the shell tools as subcommands. `ros2 run robofacts trials <subcommand>` works the same.
- The experiments root and the project root are configurable: a flag, an environment variable (`TRIALS_EXPERIMENTS_ROOT`, `TRIALS_PROJECT_ROOT`), a `trials.yaml` found by walking up from the current directory, or the nearest `experiments/` directory. No hardcoded path remains.
- `trials init <dir>` creates a project with the shared configuration, and `trials new <name>` an experiment from a commented template that passes the linter, the planner and a dry run as generated.
- Spoken operator cues: a campaign's `voice_cues` and the runner's `voice_announce` reach a laptop voice daemon over UDP (`operator_voice.py`), printed only when `TRIALS_VOICE=off`.
- The lab-specific names left the code: the stop latch path and the record profiles' robot, camera and node names are project settings in `trials.yaml`, with neutral defaults in the package, and every environment variable the package reads starts with `TRIALS_`.
- A project may ship its own gate checks in `experiments/common/preflight/checks/`; they take precedence over the packaged ones.
- `trials tool --help` lists the packaged tools and an unknown name fails with that list, `trials lint` passes pytest flags through (`trials lint -k rule_L5 -x`), and `trials ui --help` works without Flask, which only the interface itself needs (found while rewriting the lab docs to the command, 2026-10-14).
- The code stamp of a trial also describes the build: for each colcon workspace (`colcon_workspaces` in `trials.yaml`, else `.` and `ros2_ws`), the HEAD of every source repository under `src/` and the newest `install/` time, and `possibly_unbuilt` names the repositories committed after that build. A slow build query no longer costs the commit. The stop and action scripts bound the command inside the container too, so a hung stop cannot keep running there after the local client gives up.
- The page of an action that echoes a Spot `LeaseArray` states who holds the body lease in one line, with a table of every resource (the tablet held it unseen through four trials on 2026-08-10).
- A verify step for pose loss read from the drone itself, `verify_ext_pose_age` (2026-10-14): the on-board `locSrv.ageMs` of every `/<drone>/ext_pose_age` topic over the IS_FLYING window, with a declared threshold and run length, per-drone requirements (always, or only when airborne, waived before a declared date or on the simulation backend) and a one-line JSON summary for a metadata probe. The server's `Motion capture rate off` warnings, which the 2026-10-07 bags proved a bookkeeping artifact, play no part.
- Gate checks: `topic_rate.sh` takes an optional `max_hz` (a rate that must stay below a ceiling, for a level defined by a slower stream), and the new `ros_param_equals.sh node= param= expected=` compares a live node parameter with the trial's level, numerically for numbers.
- The fast path for a new experiment (2026-10-14, after creating one took an agent 44 minutes): `trials new <name> --from <existing> [--campaign <c>[:<new>]]` copies and renames a similar experiment's declarations (and a campaign) without its recorded data, notebooks or tests, `trials validate <experiment | campaign>` runs check, plan, every gate checklist's validation, the lint and the tests of that experiment and a dry run per execution host, and prints one READY or NOT READY verdict, and `trials lint --experiment <name>` lints one experiment.
- `kill_ros.sh` matches the install and build trees of any `*_ws` colcon workspace, not only `ros2_ws`, so a node of an overlay workspace (OpenVINS in `~/ov_ws`) no longer survives the clean slate.
- The T-0 gate runs on the trial's execution host (2026-10-14): a laptop-driven trial on a rig used to be gated on the laptop's processes, disk, network and stop latch. The checklist travels with the command, the verdict records `ran_on`, and an ssh failure is an error. A host spec may name `env_setup` files (an overlay workspace), and the files a spec names are sourced also when the runner executes locally inside that host's container, for the commands and the gate. The web UI's remote helpers imported `remote_exec_utils` from the wrong package level since the split, so its remote gate, stops and viewers raised ImportError; fixed, with a guard test.
- From the second adoption test of the SAC 2027 paper (2026-10-15): `trials new --from` copies a top-level or `scripts/` file only when a declaration names it, directly or through another copied file, and lists the rest under "Left out" (the source's AGENTS.md, design notes and study scripts), while an unnamed `config/` file is copied and listed for review. A code version that the probe cannot read now carries `code_version.warning`, which the runner prints as a WARNING, and a git worktree whose `.git` file names a path missing on this host (a host-made worktree used in a container) is named with its remedy, a relative `gitdir:` line.
- `kill_ros.sh` kills only the processes of the caller's `ROS_DOMAIN_ID` (read from each process's environment, unset means 0), lists the ones on other domains as left alone, and `--all` restores the kill-everything run (2026-10-15), so sessions that share a container on different domains no longer stop each other's trials.
- The test suite points at the example project through an autouse fixture, not through environment variables set at import (2026-10-15). A project that collects the package's tests next to its own (one `pytest.ini` over both) kept the example project's roots for its own tests too: under pytest 8 its config lint then checked one experiment instead of all of them, and its project-settings tests failed, in the full run only.
- The web interface, redrawn from scratch (2026-10-16, issue #131 of the lab repo): one information architecture, Experiments › experiment › campaign › trial. An experiment page lists every trial on one row (cell, status, campaign, slim bag with Foxglove and the experiment's layout, video, the analyses that include it, gate verdict, run log, metadata, code version), with blocked attempts and scratch flights, filters by campaign, status and factor, and no cap. A campaign page reads as a plan with the gate's verdicts and a per-cell count of refused attempts; a trial page plays the video and shows the verify report; an analyses page previews a cohort (`trials analyze` without `--execute`); a files view serves results and run logs read-only. Every feature of the earlier interface is kept, and its old addresses redirect.
- The words of the paper (2026-10-16): what a user reads now uses the terms the SAC 2027 paper defines, and the README has a glossary that maps each term to its file or key (file names and keys are unchanged). The planner prints wanted, covered and STILL MISSING per cell; every trial has the paper's class (usable, unverified, or excluded with its reason: aborted, quarantined, no data, scratch), and an attempt the gate refused is an attempt without a trial (`trials records --status excluded|attempt`); the gate prints `=== T-0 GATE ===`, `[gate]` and `CLEAR TO START`; the contract's messages say metadata contract and coverage axis (`factor: true`); generic text says run and action where it said fly; diagnostics are scratch recordings; the linter's rule L13 names the silent error it prevents. The machine-read tokens (GO, NO-GO, PASS, FAIL, `CHECK(S) FAILED`, `action returned rc=`, the ledger's status values) are unchanged.
- A dark mode for the web interface (2026-10-16): a switch in the top bar cycles Auto (follows the OS), Dark and Light, remembered per browser and applied before the first paint; buttons keep white text on solid fills in both themes.
- Explore mode (2026-10-16, issue #131 of the lab repo): `trials explore <campaign> [--set …] --execute`, and a 🔭 Explore button on the Experiments table, on each campaign row and in a campaign's run form (for the picked cell), bring up one condition's stack (setup steps, launch with the condition's arguments, aux launches) with a `foxglove_bridge` that may change parameters and nothing else (no topic publishing, no service calls, bound to 127.0.0.1). It runs until Stop or Ctrl-C. No T-0 gate, no recorder, no action, no metadata, no ledger line: an exploration is never coverage, and its stack is never reused by a trial. A parameter log (`explore_params.py`) starts before the stack and reads each node's parameters once through its services (the declarations a node publishes at startup are mostly lost to DDS discovery), so `runs/explore/<stamp>_explore[_<label>]/parameter_changes.yaml` lists every parameter that changed, from and to, and the ones set back. In simulation every parameter is writable by default. On hardware Explore needs an `explore:` block in `runner.yaml` whose `param_whitelist` names each writable parameter (empty by default, a live view only), lint rule L16 refuses a pattern that matches every parameter, and the UI asks for the arm checkbox. The trial livestream bridge stays read-only.
- Explore viewers (2026-10-17): `explore.viewers` in `runner.yaml`, a list of `{name, command}`, are windows for a human (a simulator GUI attached to its headless server, RViz) that Explore starts after the bridge and stops first. They change nothing in the stack, which stays the one a trial starts, a trial never runs them, and the lint checks their placeholders (L4) and script paths (L7) without counting them as a factor's consumer (L3).
- `trials records <exp>` (`trial_records.py`): every trial joined with the campaign that flew it (attempt ledger), the campaigns whose plan counts it, the slim copy, the run log and its verify lines, the gate verdict, the analyses that list it and their videos, filterable like the analyses (`--campaign`, `--status`, `--where`, `--json`). The web interface renders these records.
- The trial index and the campaign loader cache the YAML they parse by file modification time: the index of a 128-trial experiment with 27 campaigns went from 4.7 s to 0.4 s.
- CI green again (2026-10-16): the `dds_socket_buffer` gate check skips a stack that does not use CycloneDDS (`RMW_IMPLEMENTATION` other than `rmw_cyclonedds_cpp`, or unset, which on Humble means Fast DDS), so a project made by `trials init` passes its first gate on a plain ROS 2 machine; with CycloneDDS in use an unset `CYCLONEDDS_URI` still fails. `test_voice_cues.py` imports the lint module inside its test, because the lint resolves the experiments root at import and collection failed outside a project.
- An example project with the no-robot `demo_talker_listener` experiment, a quickstart script and a Docker image for the quickstart and CI.
