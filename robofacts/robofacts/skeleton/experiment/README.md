# {{name}}

Generated by `trials new {{name}}`. Declare the experiment in `config/`, then run the loop:

| file | says |
|---|---|
| `config/factors.yaml` | the axes a campaign may vary, their levels and defaults, and how the runner realizes each level |
| `config/trial_metadata_schema.yaml` | the metadata contract: the fields every trial records, `factor: true` marks a coverage axis |
| `config/preflight_checklist.json` | the T-0 gate: machine checks and operator confirmations before each trial |
| `config/runner.yaml` | how to start the system, run one trial, verify the recording, reach each computer |
| `config/analyses.yaml` | the named, repeatable analyses |
| `campaigns/baseline.yaml` | the first campaign: what to sweep, what to fix, how many repetitions |

```bash
trials lint                                                  # every declaration against the rules
trials plan experiments/{{name}}/campaigns/baseline.yaml     # what the campaign still needs
trials run  experiments/{{name}}/campaigns/baseline.yaml --limit 1              # dry run: prints the commands
trials run  experiments/{{name}}/campaigns/baseline.yaml --limit 1 --execute    # one trial for real
trials index --experiment {{name}} --summary                 # the coverage index
trials analyze {{name}} line_count --execute                 # a named analysis over the usable trials
```

The template works as generated, without any robot: `scripts/system.py` stands in for the system under test (it writes a line to a log file many times per second), the recorder stores what it writes during the trial, and `scripts/verify_log.py` checks the recording. Replace the three scripts with your own.

Recordings land in `recordings/` with a `trial_metadata.json` next to each, run logs in `runs/`, results in `results/`.
