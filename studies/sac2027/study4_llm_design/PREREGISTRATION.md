## 2. Question, conditions, models

When an LLM turns a natural-language experiment request into something runnable, do the framework's declarations checked by its validators produce designs that match the request, refuse impossible requests and record their conditions more often than a free-form launch-and-record script, and how much does the validator feedback add?

| arm | representation | feedback | calls per session |
|---|---|---|---|
| DECL_FB | declarations (a campaign, plus factor, contract and runner files where the task needs them) | the four validators of the framework guide, output returned verbatim, up to 3 rounds | 1 to 3 |
| DECL_1 | same | none: round 1 of every DECL_FB session, same prompt, which never mentions feedback | 0 extra |
| SCRIPT | one bash or Python script that launches, records, repeats and logs the conditions of each trial | none | 1 |
| SCRIPT_FB (optional, OFF) | same | a syntax check and a 60 s trace run, up to 3 rounds | 1 to 3 |

**Models (decision by Alejandro, 2026-10-01): the REDUCED tier, Claude Sonnet and Claude Haiku, at most 160 calls in total. Opus is not used.** The aliases `sonnet` and `haiku` are passed to `--model`, and the exact model identifier of every call is recorded from the JSON output (`modelUsage`).

Replicates: r = 2 independent sessions per task, model and arm. Session order: replicate 1 of every (task, model, arm), shuffled with seed 20261001, then replicate 2, shuffled the same way.

## 3. Isolation, equal context, and the exact call

Every call is exactly this command, with the prompt on stdin, from a fresh empty temporary directory:

```bash
claude -p --safe-mode --no-session-persistence --tools "" --output-format json \
    --json-schema '<harness/output_schema.json, compact>' \
    --system-prompt-file experiments/llm_design_study/packs/built/<decl|script>_<px4|talker>.md \
    --model <sonnet|haiku>
```

Checked against claude 2.1.280 on 2026-10-01 without a model call: `--safe-mode`, `--model`, `--tools`, `--output-format`, `--json-schema` and `--no-session-persistence` are in `claude --help`. `--system-prompt-file` exists but is hidden from the help text (found in the installed binary). `--bare` is not used because it accepts only an API key. Still to confirm in the pilot: that `-p --safe-mode` works with the subscription's login, and that structured output survives `--tools ""` (the CLI implements `--json-schema` as a StructuredOutput tool). If `structured_output` is absent, the harness parses the same JSON object from the `result` text, which the prompt asks for anyway.

The context packs are the four files in `packs/built/`, rebuilt byte for byte from `framework_ref` by `run_study.py packs --check`. Both packs of a setup carry the identical stack interface section (`packs/stack_<setup>.md`: hosts, shell setup, the DDS export line, the launch and its arguments, the node parameters, the topics, recording, stopping, the bag check, timing). The DECL pack adds the guide's sections on the five files and on authoring a campaign, a schema reference, the target experiment's current declarations and two example campaigns. The SCRIPT pack adds the lab's trial rules written for a script, an authoring section that mirrors the guide's, a command reference, the source of the stack's entry points and two example scripts (the same two sweeps as the example campaigns). Approximate size, 4 characters per token: PX4 9267 (DECL) against 9103 (SCRIPT), 1.8 %, talker 7519 against 7270, 3.3 %. The real input token counts are recorded per call.

The prompts (`harness/prompts.py`) share every sentence that is not about the representation: the request, the instruction to record the conditions of every trial, the rule that the stack may not be changed, the refusal rule and the output form. A declaration answer may write only `campaigns/*.yaml` and `config/{factors.yaml, trial_metadata_schema.yaml, runner.yaml, analyses.yaml, preflight_checklist*.json}`, and a script answer only `run_trials.sh` or `run_trials.py`. Other paths are ignored and reported. Rounds 2 and 3 are stateless: the task, the previous answer and the validators' output, verbatim. Every full prompt and every raw result is stored per session.

## 4. Scoring rules (automatic, no LLM judge)

### 4.1 One extractor for both representations

DECL: the runner's dry run without `--limit` (`trial_runner.py <campaign>`, in a disposable copy of the framework at `framework_ref`), for every campaign the answer writes. SCRIPT: the script runs in a bubblewrap sandbox (no network, own PID, UTS and IPC namespaces, read-only host, a throwaway copy of the repository at `framework_ref`) where `ros2`, `ssh`, `docker`, `scp`, `rsync`, `sleep` and `timeout` are shims that log every call, and where the stack's entry points (`listen_for.py`, `verify_px4_flight.py`, `kill_ros.sh`, `px4_sitl_stop.sh`) are logging stubs with the same command-line interface. Sleeps are compressed 100 times and the trace run is cut at 300 s. Later, executed artifacts are read from the witness's process table. All three sources become the same command events and go through `scorer/extract.py`:

- every command is unwrapped (`ssh <host>`, `docker exec`, `bash|zsh -c`, `timeout`, `env`, `exec`, `nohup`) and assigned to its host;
- one trial is one invocation of the setup's action (PX4: `offboard_node`, talker: `listen_for.py`, or a self-made `ros2 topic echo /chatter` under `timeout N`), with the stack and the recorder live on that host at that moment; an action with no live stack is an orphan, not a trial;
- the realized vector of a trial covers every parameter of its setup (`tasks.yaml` `setups.<setup>.parameters`), from the launch arguments and node parameters actually passed (a later `-p` wins), with the stack's own default for anything not passed; hosts are canonicalized with `host_aliases`, numbers compared as floats.

### 4.2 Metrics

| metric | frozen definition |
|---|---|
| S1 runnable without a human edit | DECL: `campaign_spec.py`, `campaign_plan.py`, the config lint and `trial_runner.py --limit 1` all exit 0 for every campaign the answer writes, the dry run lists at least one trial, and the safety screen finds nothing in any command the answer adds. SCRIPT: the safety screen passes, the trace run exits 0 within 300 s, and at least one stack launch happens. |
| S2 design match (feasible tasks only) | exact: the multiset of realized vectors equals the ground-truth expansion (cells times repetitions). Also factor precision and recall (varied parameters against swept factors), level precision and recall over (factor, level) pairs, fixed-value accuracy (a fixed factor counts as correct only if every trial holds it), repetition exactness (every realized cell has exactly the requested repetitions), trial-count error. |
| S3 correct refusal (P5, T4) | strict, the design's rule: no realized trial at all, and a non-empty `refusal` or the impossible level declared `blocked:`. Lenient (secondary): no realized trial carries an impossible level, with the same explanation condition. |
| S4 silent error | S1 holds, nothing was reported, and the realized design differs from the ground truth (feasible), or a realized or labeled trial carries an impossible level (infeasible). Reported means a non-empty `refusal`, a validator warning line (DECL), or an output line of the trace run with warn, warning or error (SCRIPT). |
| S5 condition recoverable | over the trials whose bag is local (laptop): a JSON, YAML or CSV record inside the bag directory, or anywhere in the output that names the bag directory, holds every ground-truth factor (swept and fixed, keys matched by `key_aliases`) with the realized value, and every complete record for that bag agrees on ONE condition. Static form: DECL uses the `trial_metadata.json` the runner would write (each factor under its `metadata_key`), SCRIPT the files its trace run wrote. Executed form: the same rule on the executed output, with the witness as the realized condition. |
| S6 label mismatch | some record for a trial's bag holds a ground-truth factor with a value different from the realized one. Static and executed forms as for S5. |
| S7 effort | rounds used, input and output tokens, the cost estimate and the wall time per call, from the JSON output. |

Secondary, reported but not tested: the fraction of trials with a live recorder, the fraction whose recorder covers the setup's required topics, the orphan actions, and the five outcome classes of the heatmap (exact, partial, correct refusal, silent error, not runnable).

### 4.3 Validator feedback stops when

the four validators pass and the dry run lists a trial, or the answer refuses and either writes no campaign or every failing validator refuses a `blocked:` level. Otherwise the next round goes out, up to 3.

### 4.4 Rate limits

A call is rate-limited when the result carries API status 429 or 529, or its text says so. The session is discarded (kept for audit in `results/sessions_aborted/`), not scored as a failure, and restarts from round 1 after 30 min. A rate-limit refusal that used no tokens does not count against the cap. Every other invocation does.

### 4.5 Safety screen

Before any script runs, even under the shims: refused on `sudo`, network downloads, package installs, git network operations, network access from Python, URLs, disk-level writes, system administration, killing processes it did not start, privileged containers, writes to the home or system directories, hardware access, obfuscated code, and a recursive delete outside `$OUTPUT_DIR` or `/tmp`. A refused script is not runnable with the reason "unsafe" and is never edited. The same screen runs over every command a declaration answer adds.

### 4.6 The scorer's own validation (freeze condition)

Every gold answer scores perfect, and every one of the 23 mutants in `gold/broken/manifest.yaml` shows exactly its intended defect (`tests/test_llm_study_scorer.py`, `run_study.py validate-scorer`). Gold: 12 declaration answers (two variants each for P5 and T4: the plain refusal and the blocked declaration) and 10 script answers (the two infeasible ones are refusals). Mutants: a wrong level, a wrong repetition count, a dropped level, an unrecorded factor (no `metadata_key`, and a `metadata_key` the contract does not declare), a factor that varies the wrong thing, an unapplied factor, a silent label mismatch, an accepted infeasible request (twice), a host left at its default, a crashing script, an unsafe script, a stack stopped before the mission, and one bag shared by all trials.

## 5. Hypotheses

- **H3.1** S2 exact is higher for DECL_FB than for SCRIPT, pooled over the two models, one-sided. Falsified if SCRIPT matches or exceeds it.
- **H3.2** S2 exact is higher for DECL_FB than for DECL_1. Falsified if no session improves after feedback.
- **H3.3** No executed DECL artifact records a label that differs from the realized condition (executed S6 = 0), and S4 is lower for DECL_FB than for SCRIPT. Falsified by one executed DECL label mismatch, or by S4 not lower.
- **H3.4** S3 (strict): DECL refuses the infeasible requests more often than SCRIPT. Falsified if SCRIPT refuses as often.
- **H3.5** S5: every executed DECL trial is recoverable. Since `f39172bc82` the validators refuse a swept factor that is not a recorded axis (Section 9, item 7), so this holds by construction for every runnable DECL artifact, and the informative number is the SCRIPT rate under an explicit instruction to log the conditions. It is still measured on the executed bags, not assumed.
- **H0** Representation and feedback do not change S2, S3, S4 or S5.

## 6. Analysis plan

Pairs are (task, replicate) within a model. S2 is defined for the 8 feasible tasks, so 16 pairs per model and 32 pooled. S3 has 2 tasks, so 4 pairs per model, reported descriptively only. Tests: the exact McNemar test per model for DECL_FB against SCRIPT, DECL_1 against SCRIPT and DECL_FB against DECL_1, and a Mantel-Haenszel test stratified by model for the pooled comparison. An exact McNemar test needs at least 6 discordant pairs, all in one direction, for p below 0.05, so only large effects can show, and the study is reported mainly descriptively with Wilson 95 % intervals for every rate. The external subset is reported separately and never pooled with the author's tasks. Paper Table 5: rows are model times arm (2 times 3 = 6 rows), columns S1, S2 (exact and level F1), S3, S4, S5, S6, rounds, tokens.

## 7. Call budgets

| tier | models | sessions | maximum calls | expected calls | status |
|---|---|---|---|---|---|
| full | Haiku, Sonnet, Opus | 120 | 240 | about 170 | refused by the harness |
| **reduced** | **Sonnet, Haiku** | **80** | **160** | **about 115** | **the pre-registered tier** |
| minimum | Sonnet | 40 | 80 | about 60 | fallback, allowed |
| optional SCRIPT_FB | Sonnet | 20 | 60 | about 40 | off |

Reduced tier, per model: 40 sessions, 40 to 80 calls (Sonnet and Haiku alike). Per arm: DECL_FB 40 sessions, 40 to 120 calls, SCRIPT 40 sessions, 40 calls. The expected count assumes, as the design did, that about half of the DECL_FB sessions pass in round 1.

The hard cap of 160 covers EVERY call of the study: the pilot (P1 and T1, Sonnet, both arms, 4 sessions, 4 to 8 calls, not analyzed), the main grid, the external subset, and the optional arm. `harness/budget.py` reserves each session's worst case before starting it, so the cap holds even if every session uses all its rounds. At worst case the main grid alone needs the full 160, so the pilot's calls would leave the last replicate-2 sessions unstarted, and the external subset can run only from what the expected case leaves (about 160 - 115 - 6 = 39 calls, at most 16 per external task). The harness also throttles to 20 calls per rolling hour.

## 8. Execution in simulation

Replicate 1 of every task, model and arm, final artifact only (DECL_FB final and SCRIPT), runnable artifacts only, infeasible tasks skipped when correctly refused, and only the trials the task's `execute` field allows (T3 and P5: laptop trials). At most 40 artifacts under the reduced tier. Each runs in its own `docker run --rm` container from the dev image, with no network, a separate `ROS_DOMAIN_ID` (77), its own PID namespace, a timeout, the repository mounted read-only, a throwaway experiments directory at `framework_ref` holding the artifact, one writable output directory, and the witness sampling the process table. `harness/executor.py` builds these commands. It is run only by the agent that owns the simulator, one container at a time.

## 9. Changes from the design note, with reasons

1. **Location.** The design suggested the paper repository (`study/llm_design/`), not `experiments/`, because the lint would treat it as an experiment. The brief placed it in `experiments/llm_design_study/`. Verified safe: every discovery glob of the lint, the index, the planner and the UI matches `experiments/*/config/...` or `experiments/*/campaigns/*.yaml` at depth one, and this folder has neither, so nothing treats it as an experiment. The anonymized snapshot copies it into the paper repository.
2. **Two models, not three** (Alejandro's tier decision). Mantel-Haenszel has two strata, the table six rows.
3. **One cap for everything.** 160 is the total, so the pilot and the external subset come out of it (Section 7).
4. **S2 pairs.** The design counted 20 pairs per model (10 tasks times 2). S2 is undefined for the 2 infeasible tasks, so 16 pairs per model for S2.
5. **S3 has a strict and a lenient form.** The strict one is the design's rule. The lenient one records answers that run only the feasible part and state why, which the strict rule cannot tell apart from a plain refusal.
6. **S5 and S6 are also computed statically** (dry run and trace run), over local trials, and require one consistent condition per bag. Found while validating the scorer: a bag shared by all trials passed the first version of the rule because each trial's CSV row named the shared bag.
7. **The metadata-contract check.** At the first freeze (`5e272c6e79`) it only warned: `campaign_spec.py` and `campaign_plan.py` printed a warning and exited 0, while the guide said "refused", and a swept factor with no `metadata_key` made the planner merge its levels so that the dry run flew every trial at the first level. The framework fix `f39172bc82` (2026-10-02) makes it a hard refusal in `campaign_spec.py`, `campaign_plan.py` and `trial_runner.py` (exit 2, naming the factor), and `run_plan` raises before any trial. **Decision: no fifth validator.** Three of the guide's four validators now refuse such a campaign, and their output reaches the model verbatim in the feedback rounds, so a separate contract check would only repeat the same message. The validator list shown to the models stays the guide's four, and the schema reference in the DECL pack now states the refusal. Mutant `D_P3_unrecorded_factor` changed from "runnable, warned, S5 false" to "not runnable", and `D_P4_not_in_contract` (a `metadata_key` the contract does not declare) was added. Both are refused by `campaign_spec`, `campaign_plan` and the dry run.
8. **Trace sandbox.** The design ran script traces in a disposable container. The trace run starts no ROS process (only shims), so it runs in a bubblewrap sandbox on the host: no network, own namespaces, read-only host, about 1 s per script, and no competition with the simulator's container. The real executions keep the container (Section 8).
9. **Pack contents.** The design gave the SCRIPT pack one example script. Reaching the 10 % token balance needed more script-side material: the lab's trial rules for a script, an authoring section that mirrors the guide's, the stack's entry-point sources, a command reference, and two example scripts that mirror the two example campaigns. Every addition is information a script author can use, so the comparison stays conservative for the framework.
10. **Realized talker rate.** `chatter_rate` changes how long the listener runs, not the talker's publishing rate. A trial's rate is what `listen_for.py --rate` received, or, for a self-made listener, the level whose duration equals its `timeout`. Verified at freezing: `listen_for.py` accepts only `slow` and `fast`, so T4 is infeasible as stated.
11. **P5 and T4 execution.** Executed only when the answer was not a correct refusal, so the run shows what the answer really did.
